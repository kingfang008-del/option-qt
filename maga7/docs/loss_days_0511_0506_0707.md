## 3. 问题归类（不是「30 分钟太长」这么简单）

1. **入场质量 / 假突破**：Rule-A 触发后股票几乎不继续、甚至立刻反向；期权杠杆把小反向放大成 −30%～−60%。  
2. **硬止损只挡极端**：`sl_mult=0.40` → 约 −60% 才 SL；05-06 / 07-07 在 −30%～−40% 磨到 T+30，**从未触发 SL**。  
3. **`mae_cut` 配置了但没生效**：profile 有 `mae_cut_ret=0.25` 等字段，但 `exit_mode=hold_extend` **未包含** `+mae_cut`，代码只认 `exit_mode`/`early_exit_mode` 字符串里的 `mae_cut`。  
4. **Hunt 不是元凶**：05-11 仅 armed；三次大亏都是 baseline。

## 5. 要不要「实时跟踪分析」？

**要的是持仓期 MTM 跟踪，不是再叠一层复杂分析系统。**

| 已有 | 缺口 |
|------|------|
| TP / SL / T+30 / hold_extend（MTM≥0 才延到 45） | 输家从不开 extend，但会 **磨满 30m** |
| profile 里的 mae_cut 参数 | **未接入 exit_mode** → 形同虚设 |
| Watchdog L1（日初） | 管不开仓，**不管持仓中毒性路径** |

建议优先级：

1. **P0 工程**：确认并修复 wiring——要么 `exit_mode=hold_extend+mae_cut`，要么 `early_exit_mode=mae_cut`；现参已在 JSON 却不生效。  
2. **P1 研究**：双窗（May–Jul / Feb–Apr）验收 `+mae_cut`；对照更紧档（15%/3m）是否伤赢家。  
3. **不必**先上独立「实时分析服务」；replay/live 已在 1s quote 上跑 `simulate_trade`——把 toxic-cut 接上即是实时跟踪。  
4. **可选增强**（次优先）：入场时 `mf10` 与方向冲突则 scale/block（07-07 DN 但 mf>0）；或 DN 在 QQQ 翻红时软退——需单独消融，勿与 mae_cut 一次全开。
